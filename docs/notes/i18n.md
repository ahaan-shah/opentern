# Notes: languages

Keep it current: update it in the same commit as the code.

Built Nov 2026 (the maintainer's call: from scratch rather than from PR #1; the
language list and system-tag matching were modelled on Spotifast, MIT, whose clone
lives in the git-ignored `opensource-help/`). English plus German, Spanish, French,
Portuguese (Brazil), Swedish, Russian, Hindi, Japanese and Simplified Chinese.

## Rules (from the maintainer)
- English text is the key; anything untranslated shows in English.
- Scripts, saved names, tickers, company names and news stay untranslated.
- Switching is instant. Settings → General → Language (System first). Onboarding has no
  picker: it follows the system's language, else English.
- Translate everything that makes sense, metrics included (Profit factor, Sharpe ratio).
- **Nothing the agent reads is translated**: tool answers, `status` strings, indicator
  and tab names stay English.

## How it works (`crates/app/src/i18n.rs`)
- `tr("…")` where it's drawn; `trf!("…{x:.2}…")` takes exactly what `format!` takes (the
  proc macro in `crates/i18n-macros`; specs are left out of the key, `{}` becomes `{0}`);
  `trc("price", "Close")` for a word with two meanings; `date(&z, "%a %d %b")` for dates
  (the pattern is a key too, so a language can reorder it).
- **Names and stored messages stay English** (`nt!`, `msg!`) and are translated where
  they're drawn: `tr(x.name())`, `trm(&self.lab.status)`, `trl(label)` for agent steps,
  `of_study(meta, s)` for an indicator's texts (a built-in's are ours, a script's aren't).
  `trm` finds the template a message was made from and puts the values back. Values are
  never translated, except `{e}` and `{what}`, which hold another message: a permission
  prompt always shows a command or a file exactly.
- The catalogs are gettext files, `crates/app/locales/<code>.po`, built in; one is read
  when first used, into a sorted table of slices (English costs nothing).
- Plurals: the English code picks "1 chart" or "{n} charts"; languages with more forms
  word it around the number ("Графиков: {n}").

## Adding or changing a text
Wrap it as above, then `UPDATE_POT=1 cargo test -p opentern the_template` (updates
`messages.pot` and every `.po`, keeping translations; new ones start empty) and fill in
the `.po` files. A test fails while the template is stale. `cargo test -p opentern
audit_untranslated -- --ignored --nocapture` opens every page with translated text in
brackets and lists what's drawn without.

Texts from other crates are listed by `NAMES` and `ERRORS` in `i18n_tests.rs`; a new
name function or error file goes there.

## Adding a language
A `Lang` variant, its `.po`, and for a new script a font in `scripts/i18n-fonts.py`.

## Fonts
The interface fonts are Latin only, and many computers have no Chinese or Japanese
font, so `assets/fonts/i18n/` has subsets with what the catalogs use (Inter's Cyrillic,
Noto Sans Devanagari, JP, SC; two weights; about 1.3 MB). Re-run
`scripts/i18n-fonts.py` after changing the Japanese or Chinese catalog, or a test names the
missing characters. egui shapes text (HarfBuzz's port), so Hindi's conjuncts and vowel
signs are right. Right-to-left languages would need more. A Chinese or Japanese news headline
or typed name can still show boxes: only the interface's characters are there.

Not translated: the What's New cards of past releases, the timezone picker's cities,
exchanges' own names, indicator short names (RSI, BB), script errors, startup failures, logs.

The translations were written by Claude and no native speaker has checked them.
